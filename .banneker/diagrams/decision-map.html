Architecture Decision Map

Key technical decisions and their rationale

Platform Strategy

Multi-Platform Support

→ macOS + Linux + Termux + Windows
Single repo serves all personal devices. install.sh auto-detects platform and installs appropriate packages.

Package Manager Abstraction

→ brew / apt / pkg wrapper functions
Idempotent install functions (brew_install, apt_install, termux_install) handle platform differences transparently.

Symlink Strategy

→ Symlink dotfiles, copy directories
Files are symlinked for instant updates. Directories (helix, termux) are copied to avoid nested symlinks.
Shell & Editor

Shell Choice

→ Zsh (primary) + Bash (fallback)
Zsh with oh-my-zsh for productivity. Bash config maintained for scripts and Docker.

Editor Strategy

→ Helix + Neovim (dual editors)
Helix for modern modal editing, Neovim for ecosystem compatibility. Both configured with LSP support.

Prompt System

→ Starship (cross-shell)
Single prompt config works across bash, zsh, and fish. Fast Rust-based implementation.

Completion System

→ Carapace
Universal shell completions for 600+ CLI tools. Covers gaps in native completions.
Infrastructure

Docker Environment

→ Python 3.12-slim base
Lightweight base image. Tools installed via apt + official installers. Useful for project analysis without host contamination.

UID/GID Matching

→ Build args USER_ID/GROUP_ID
Mounted host files maintain correct ownership. Prevents permission issues in container.

Cache Strategy

→ Named Docker volume for uv cache
Python package cache persists across container runs. Reduces network usage and startup time.
Mobile (Termux)

Battery Management

→ Custom chargectl daemon
Root-only daemon limits charge to 90%. Prevents battery degradation on always-connected devices.

Boot Persistence

→ Magisk module + Termux login hook
Dual approach: Magisk for true boot start, termux-login.sh for session start. Covers all scenarios.
